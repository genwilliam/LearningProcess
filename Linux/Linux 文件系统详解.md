# Linux 文件系统详解**





Linux 文件系统是 Linux 操作系统的核心组成部分，也是理解 Linux 系统运作的关键之一。理解文件系统不仅仅是学会存储数据，更是理解内核如何管理磁盘、分区和设备的重要基础。本文将带你深入理解 Linux 文件系统，从目录结构到分区、挂载、inode，再到符号链接和硬链接，一步步梳理清楚。



------





## **1. 文件系统层次结构**





Linux 的文件系统是树状结构，根目录 / 是整个系统的起点。常见的目录如下：



- /：根目录，所有内容都在此目录下。
- /bin：必要的二进制程序，如 ls、cp。
- /boot：内核和引导文件。
- /dev：设备文件。
- /etc：核心系统配置文件。
- /home：普通用户的个人目录。
- /lib：系统和程序的库文件。
- /media：可移动设备挂载点。
- /mnt：临时挂载的文件系统。
- /opt：可选软件包。
- /proc：内核和进程信息。
- /root：root 用户目录。
- /run：启动以来的运行信息。
- /sbin：系统管理二进制文件。
- /srv：特定服务数据。
- /tmp：临时文件。
- /usr：用户安装的软件和工具。
- /var：可变数据，如日志、缓存等。





> 小提示：根目录下的内容非常多，但掌握常用目录即可高效操作系统。



------





## **2. 文件系统类型**





Linux 支持多种文件系统，每种文件系统都有不同的特点：



- **ext4**：当前 Linux 默认文件系统，稳定、兼容性好，支持大容量卷和大文件。
- **Btrfs**：新型文件系统，支持快照、增量备份。
- **XFS**：高性能文件系统，适合大文件存储。
- **NTFS / FAT**：Windows 文件系统。
- **HFS+**：Mac 文件系统。







### **日志功能**





大多数 Linux 文件系统都有日志功能（journal），保证系统在异常断电后仍保持一致性，减少文件系统检查时间。





### **虚拟文件系统 (VFS)**





Linux 提供 VFS 层，让应用程序可以透明地访问不同类型的文件系统，而无需关心底层实现。



------





## **3. 磁盘与分区**







### **磁盘与块设备**





每块磁盘对应一个块设备，例如 /dev/sda。通过分区，可以在同一块磁盘上创建多个逻辑区域，如 /dev/sda1、/dev/sda2。





### **分区表**





分区表记录磁盘的分区信息，包括分区起始、结束、类型等。主要有两种：



- **MBR**（Master Boot Record）：传统分区表，最多四个主分区，可通过扩展分区添加逻辑分区，支持最大 2TB 磁盘。
- **GPT**（GUID Partition Table）：新标准，分区数量不受限制，每个分区有唯一 GUID，常与 UEFI 引导结合使用。







### **分区结构**





每个分区上可以创建文件系统或专用用途（如 swap 交换空间）。文件系统结构通常包括：



- **引导块**：存放操作系统引导信息。
- **超级块**：文件系统元信息，如 inode 表大小、逻辑块大小。
- **inode 表**：管理文件的数据库，每个文件对应一个 inode。
- **数据块**：实际存储文件和目录的区域。





------





## **4. 创建文件系统**





在分区上创建文件系统非常简单：

```
sudo mkfs -t ext4 /dev/sdb2
```



- -t：指定文件系统类型。
- /dev/sdb2：目标分区。





> 注意：不要在已有文件系统上随意创建，否则可能破坏数据。



------





## **5. 挂载与卸载**





挂载让文件系统内容在系统中可访问。挂载步骤：



1. 创建挂载点：



```
mkdir /mydrive
```



1. 挂载分区：



```
sudo mount -t ext4 /dev/sdb2 /mydrive
```



1. 卸载：



```
sudo umount /mydrive
# 或
sudo umount /dev/sdb2
```



### **使用 UUID 挂载**





UUID 是设备唯一标识，保证挂载不会因为设备名变化而出错：

```
sudo blkid
sudo mount UUID=130b882f-7d79-436d-a096-1e594c92bb76 /mydrive
```



------





## **6. 自动挂载** 

## **/etc/fstab**





如果想在系统启动时自动挂载文件系统，可以编辑 /etc/fstab：

```
UUID=130b882f-7d79-436d-a096-1e594c92bb76 /               ext4    relatime,errors=remount-ro 0 1
UUID=78d203a0-7c18-49bd-9e07-54f44cdb5726 /home           xfs     relatime               0 2
UUID=22c3d34b-467e-467c-b44d-f03803c2c526 none            swap    sw                     0 0
```

字段说明：



- UUID：设备唯一标识。
- 挂载点：文件系统挂载到的目录。
- 文件系统类型
- 挂载选项
- Dump（备份用）
- Pass（fsck 检查顺序）





> 修改 fstab 要小心，出错可能导致系统无法启动。



------





## **7. 交换空间 (Swap)**





交换分区用于虚拟内存，当物理内存不足时，系统会将闲置进程的内存数据写入 swap。

```
sudo mkswap /dev/sdb2
sudo swapon /dev/sdb2
# 启动时持久启用需写入 /etc/fstab
sudo swapoff /dev/sdb2  # 关闭 swap
```

> 现代系统通常 RAM 足够大，swap 可以适量配置即可。



------





## **8. 磁盘使用与文件系统检查**





- 查看磁盘空间：



```
df -h
```



- 查看目录磁盘使用：



```
du -h
```



- 修复文件系统：



```
sudo fsck /dev/sda
```

> df 用于磁盘空闲情况，du 用于目录占用情况。fsck 用于文件系统修复，尤其在异常关机后。



------





## **9. Inode**





每个文件在文件系统中都有一个 inode，存储文件元信息：



- 文件类型、权限、所有者
- 时间戳（创建、修改、访问）
- 文件大小、块数量
- 数据块指针（前 12 个直接指向，后续指向间接块）





查看 inode：

```
df -i       # 查看剩余 inode
ls -li      # 查看文件 inode
stat 文件   # 查看详细 inode 信息
```

> Inode 是文件的“身份证”，数据存储依赖 inode 指针找到实际块。



------





## **10. 链接**





Linux 提供两种链接：





### **符号链接（软链接）**





类似 Windows 快捷方式，通过文件名指向目标文件，跨文件系统可用：

```
ln -s myfile mylink
```



### **硬链接**





直接链接到同一个 inode，多条硬链接修改文件内容会相互影响，不能跨文件系统：

```
ln myfile2 myhardlink
```

> 链接计数显示 inode 被引用的次数，只有当所有硬链接删除后 inode 才会被释放。



------





## **11. 总结**





Linux 文件系统是整个系统的基础。掌握以下内容尤为重要：



1. 目录结构与层次 /。
2. 磁盘分区与分区表（MBR / GPT）。
3. 创建文件系统、挂载与卸载。
4. 使用 UUID 和 /etc/fstab 自动挂载。
5. 磁盘使用、fsck 检查。
6. Inode 及其结构。
7. 符号链接与硬链接的区别与使用。





理解文件系统不仅能帮助你管理数据，还能让你更深入理解 Linux 系统的运作方式。
