# **理解 Linux 设备：从** /dev 到 udev

其实我们每天都在用各种“设备”——硬盘、U 盘、显示器、键盘、鼠标……

但在 Linux 眼里，这些都只是“文件”。没错，**一切皆文件（Everything is a file）**。

所以当你在和一个磁盘打交道时，Linux 其实是通过一个“设备文件（device file）”在 /dev 目录下和它交流的。

## **1. /dev：设备的大本营**

/dev 目录是所有设备文件的集中地。

这些文件不是普通意义上的文本文件，而是指向系统实际硬件或虚拟设备的**接口**。

你可以把它理解成“现实设备”和“系统世界”之间的翻译官。

程序不会直接访问硬盘，而是通过 /dev/sda 这样的设备文件来读写数据。

设备文件主要分两类：

- **字符设备（Character Device）**：一次处理一个字符，比如键盘、鼠标、串口。
- **块设备（Block Device）**：一次处理一个数据块，比如硬盘、U 盘。

## **2. 常见设备命名规则**

在现代 Linux 系统中，大部分存储设备都以 **SCSI（Small Computer System Interface）** 协议的方式表示。

哪怕你根本没有真的 SCSI 硬件，Linux 也会这么命名。常见形式如下：

| **设备文件** | **含义**               |
| ------------ | ---------------------- |
| /dev/sda     | 第一个硬盘             |
| /dev/sdb     | 第二个硬盘             |
| /dev/sda1    | 第一个硬盘的第一个分区 |
| /dev/sda3    | 第一个硬盘的第三个分区 |

在一些老旧系统中，还能看到用 hd 开头的命名，比如：

| **设备文件** | **含义**               |
| ------------ | ---------------------- |
| /dev/hda     | 第一个 PATA 硬盘       |
| /dev/hdd2    | 第四个硬盘的第二个分区 |

## **3. 伪设备（Pseudo Devices）**

有些设备其实并不真实存在，它们是 Linux 自己虚构出来的，用来提供特殊功能：

| **设备文件** | **作用**                             |
| ------------ | ------------------------------------ |
| /dev/null    | 黑洞，所有输入都被吞掉，不产生输出   |
| /dev/zero    | 输出连续的零字节流                   |
| /dev/random  | 输出随机数流（可以用来生成随机数据） |

这些伪设备经常出现在脚本或测试命令里，比如：

```
cat /dev/zero > bigfile.img
```

这行命令会创建一个充满零的假文件，挺适合拿来测试磁盘性能的。

## **4.** **/sys 与 sysfs：更细的设备信息**

Linux 后来引入了一个叫 **sysfs** 的虚拟文件系统，用来补充 /dev 的不足。

它一般挂载在 /sys 目录下，保存着系统中所有设备的详细信息，比如制造商、驱动、插入位置等等。

如果说 /dev 是“设备入口”，那 /sys 就是“设备档案馆”。

比如看看 /sys/block/sda：

```
ls /sys/block/sda
alignment_offset  size  queue  device  stat  ...
```

这些都不是可以“读写”的设备节点，而是告诉你设备当前状态的数据文件。

换句话说，你不通过 /sys 去“用”设备，而是去“了解和管理”设备。

## **5. udev：自动化设备管理大师**

早期的 Linux 需要手动用 mknod 命令创建设备节点，比如：

```
mknod /dev/sdb1 b 8 3
```

主设备号、次设备号这些数字得自己查，挺折腾。

而现在，感谢 **udev**，这一切都自动化了。

udevd 守护进程会监听内核事件（比如你插了个 U 盘），然后根据规则动态创建或删除 /dev 下的文件。

这些规则通常定义在 /etc/udev/rules.d/ 里。

你可以通过以下命令查看某个设备的详细信息：

```
udevadm info --query=all --name=/dev/sda
```

这条命令能列出设备的属性、驱动、序列号等丰富数据，调试或写规则时非常有用。

## **6. 常用设备信息工具**

有几个命令非常常见，推荐熟悉一下：

| **命令** | **功能**                          |
| -------- | --------------------------------- |
| lsusb    | 列出所有 USB 设备                 |
| lspci    | 列出所有 PCI 设备（显卡、网卡等） |
| lsscsi   | 列出 SCSI 设备（包括硬盘、光驱）  |

这些命令有点像 ls 的“亲戚”，只是它们列的是“设备”而不是“文件”。

## **7. dd：强大的复制与转换工具**

dd 是一个非常古老但依然强大的工具，用来复制或转换数据流。

基本语法如下：

```
dd if=/path/to/input of=/path/to/output bs=1M
```

示例：

```
dd if=/home/pete/backup.img of=/dev/sdb bs=1024
```

这会把 backup.img 的内容写入到 /dev/sdb（整个硬盘）中。

常用参数说明：

- if：输入文件（input file）
- of：输出文件（output file）
- bs：块大小（block size），如 1M、512k 等
- count：复制的块数（可选）

⚠️ **警告**：dd 的强大意味着危险。

写错目标设备（比如把系统盘当作 of）可能直接导致数据蒸发 💥。

## **✨ 总结一下**

| **概念**               | **作用**                           |
| ---------------------- | ---------------------------------- |
| /dev                   | 存放设备文件，程序通过这里访问设备 |
| /sys                   | 存放设备信息和属性                 |
| udev                   | 动态管理设备节点                   |
| lsusb / lspci / lsscsi | 查看不同类型的设备信息             |
| dd                     | 复制、备份或恢复设备数据的瑞士军刀 |

其实理解了这几块内容，你就能看透 Linux 对“设备”的那套哲学：

**抽象、统一、自动化。**

现实世界的硬件千奇百怪，但在 Linux 眼里，它们都能以文件的形式被管理、被访问、被理解。

这就是它的优雅所在。
