# **粘滞位（Sticky Bit）——让文件“粘”住**



我们前面讲过读、写、执行权限，还有 SUID、SGID 这些特殊权限。现在，让我们聊聊最后一个有趣的小家伙——**粘滞位（Sticky Bit）**。



## **为什么需要粘滞位？**



先想一个场景：

假设有一个公共目录，比如 /tmp。

所有人都能往里面放文件，也能编辑自己的文件。听起来挺合理，对吧？



但是！

如果没有额外的保护，任何人都可以删除别人的文件。

这就尴尬了 —— 我辛苦保存的临时日志，你一不小心就给删了。



所以 Linux 给我们准备了一个解决方案：

👉 **粘滞位（Sticky Bit）**。



它的作用就是：



> 让目录中的文件“粘”在它们的所有者身上，别人不能随便删除或修改。

## **实际例子看看**



我们用 ls -ld /tmp 看一下系统的临时目录：

```
$ ls -ld /tmp
drwxrwxrwx+t 6 root root 4096 Dec 15 11:45 /tmp
```

注意到最后那个小写的 t 吗？

没错，那就是粘滞位的标志。



/tmp 目录的权限是 drwxrwxrwx+t ——

意思是：



- 每个人都能读、写、进入；
- 但只有**文件的拥有者**或 **root 用户** 才能删除文件。



所以你可以在 /tmp 里随便创建自己的文件，但别人删不了。

这对于公共目录来说非常重要，比如 /tmp、/var/tmp 等。



## **怎么设置粘滞位？**





你可以通过两种方式为目录添加粘滞位。

### **1. 符号方式**



```
sudo chmod +t mydir
```

这会在目录 mydir 上添加粘滞位。



如果想取消：

```
sudo chmod -t mydir
```



### **2. 数字方式**



粘滞位对应的八进制数字是 **1**。

所以完整权限写法是：

```
sudo chmod 1755 mydir
```

这里的 1 就是粘滞位，而后面的 755 是普通的权限部分。

(如果是 SUID 是 4，SGID 是 2，粘滞位就是 1，所以有时候也写作 chmod 4755、2755、1755 这种格式。)



## **小结一下**



| **特殊位**           | **八进制值** | **作用**             | **示例标识**      |
| -------------------- | ------------ | -------------------- | ----------------- |
| SUID                 | 4            | 以文件所有者身份执行 | rws               |
| SGID                 | 2            | 以组身份执行         | rwx → rws（组位） |
| 粘滞位（Sticky Bit） | 1            | 限制文件删除         | 目录权限末尾 t    |

简单记法：



> SUID 给程序权限

> SGID 给组继承权限

> 粘滞位保护共享目录





## **写在最后**



粘滞位虽然听起来像是个不起眼的小权限位，但它的存在让多用户系统变得更安全、更有秩序。

你可以把它想象成“共享空间的门锁”——大家都能进出，但只有自己的东西自己能动。



所以下次当你在 /tmp 里乱丢临时文件的时候，不妨 ls -ld /tmp 看一眼。

看到那个 “t”，就说明这扇门锁已经帮你守好了。
