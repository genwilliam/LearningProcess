# **稍微聊聊 Linux 的进程权限**

我们前面讲过文件权限，这次想带你看看进程的权限系统。很多人第一次接触 Linux 的时候，都会对 “为什么我运行某个命令会提示权限不够？” 感到困惑。更有意思的是，有些命令（比如 passwd）明明是普通用户运行的，却能修改系统文件。这到底是怎么做到的？

## **权限，不止一个 UID**

Linux 的权限系统设计得挺精妙的。别看只有一个用户在运行命令，实际上，每个**进程**背后都藏着好几个“身份标签”，也就是不同的 UID（User ID）。一般来说，主要有三个：

1. **真实用户 ID（Real UID）**

   这表示是谁启动了这个进程。比如你是 william 用户，那么你运行的命令的真实 UID 就是你的用户 ID。系统用它来追踪是谁干的这件事。

2. **有效用户 ID（Effective UID）**

   这个才是决定“权限”的关键。系统在判断一个进程能不能访问文件、能不能执行某些操作时，看的是这个 UID。

   举个例子，你执行 touch a.txt，这个进程的有效 UID 就是你自己，所以创建出来的文件也是你的。

3. **保存的用户 ID（Saved UID）**

   这个有点像“备用身份”。当程序需要临时用更高权限（比如 root）干一件事时，可以先切换到高权限 UID，干完再切回去。

   这在安全上非常重要，避免程序长时间带着高权限乱跑。

## 以 **passwd 命令为例**

我们来看看一个非常经典的例子：passwd。

这个命令的功能是修改密码。问题是，密码是存在 /etc/shadow 里的，这个文件普通用户根本没权限改。

那为什么我们却能用 passwd 改自己的密码呢？

关键就在 **SUID（Set User ID）**。

这个权限位的意思是：当你执行这个程序时，**暂时用文件所有者的身份运行**。

passwd 的拥有者是 root，所以它会以 root 身份运行。

也就是说：

- 你运行 passwd 时，你的**真实 UID** 是你自己，比如 1000；
- 但程序的**有效 UID** 临时变成了 root（UID 0）。

这样 passwd 就能修改系统文件了。

不过别以为你就能趁机改别人的密码。Linux 不是这么好骗的。

系统会看：你当前进程的真实 UID 是谁？如果不是 root，就只能改自己的密码。

这就是为什么你没法直接改别人的账户。

## **为什么要搞这么复杂？**

其实很好理解：

有些程序确实需要暂时的“特权”去干一件必须的事（比如修改系统配置），但又不希望一直保持超级权限。

所以，Linux 就设计了三层 UID，让程序能在“普通模式”和“高权限模式”之间安全地切换。

这也是为什么很多系统命令都带 SUID 的原因。

## **总结一下**

| **UID 类型** | **作用**     | **举例**     |
| ------------ | ------------ | ------------ |
| 真实 UID     | 谁启动了进程 | 追踪用户身份 |
| 有效 UID     | 决定权限     | 控制文件访问 |
| 保存 UID     | 临时保存特权 | 安全切换身份 |

简单来说：

> **真实 UID** 是“你是谁”，

> **有效 UID** 是“你现在能干什么”，

> **保存 UID** 是“你还有没有备用身份”。

---

Linux 的安全体系就是这样一环扣一环的设计。

很多人觉得命令行冰冷，其实背后充满了逻辑和哲学。

你可以想想：要是所有程序都能任意切换权限，那这个系统早就乱套了。

所以，下次当你看到一个命令需要 root 权限，不妨想想它背后到底是怎么运行的，这也是理解 Linux 的乐趣所在。
