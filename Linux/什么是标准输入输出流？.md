# **什么是标准输入输出流？**





先别急着看术语，咱打个比方。



想象你在餐厅点餐：



- 你 **说出口**（给厨师点菜） 👉 就像“输入”
- 厨师 **回应你**（告诉你菜好了） 👉 就像“输出”
- 厨师 **抱怨一句锅坏了** 👉 就像“错误输出”





Linux 的命令行，其实就像这样一场“对话”：

你给命令**喂输入**，命令**吐输出**，出错的时候再**抱怨一声**。



------





# **三个核心角色**





在 Linux 里，几乎所有命令都和这三个“流（stream）”打交道：

| **名称** | **文件描述符** | **方向** | **默认设备** | **含义**                       |
| -------- | -------------- | -------- | ------------ | ------------------------------ |
| stdin    | 0              | 输入     | 键盘         | 标准输入（Standard Input）     |
| stdout   | 1              | 输出     | 屏幕         | 标准输出（Standard Output）    |
| stderr   | 2              | 输出     | 屏幕         | 标准错误输出（Standard Error） |

Linux 世界里，一切皆文件（Everything is a file）。

所以这三个其实就是三个特殊的“文件通道”，编号分别是 **0、1、2**。



------





# **举个最简单的例子**





我们敲个命令：

```
echo "Hello, Linux!"
```

这时：



- stdin：没有输入；
- stdout：把“Hello, Linux!”送到屏幕；
- stderr：也没报错。





但如果你输错了：

```
cat not_exist_file.txt
```

这时：



- stdout：没有输出；
- stderr：报错信息显示在屏幕上。





换句话说：



> **stdout 是程序的正常输出，而 stderr 是程序的“吐槽”。**



------





# **重定向（Redirection）**





我们常听到的 “>”、“>>”、“2>”、“&>” 其实就是在控制这些流往哪儿流。





### **把标准输出保存到文件**



```
echo "hello" > out.txt
```

意思是：

别把输出显示到屏幕上了，把它**重定向到 out.txt 文件**。





### **把错误输出保存到文件**



```
cat not_exist.txt 2> error.txt
```

这里 2> 的意思是：



> “把编号为 2 的流（stderr）写进 error.txt”





### **同时保存标准输出和错误输出**



```
command > all.log 2>&1
```

或者更简洁：

```
command &> all.log
```

这句的逻辑是：



> “把 stdout（1）和 stderr（2）都重定向到同一个地方。”



------





# **反向操作：从文件读输入（stdin）**





除了输出，我们也能把输入改成从文件里来，比如：

```
wc -l < myfile.txt
```

这里 < 就是告诉命令：



> “别从键盘读，去 myfile.txt 里读。”



相当于：

```
cat myfile.txt | wc -l
```

这就是输入重定向。



------





# **小结一下**



| **操作**             | **符号** | **示例**            | **含义**               |
| -------------------- | -------- | ------------------- | ---------------------- |
| 标准输出重定向       | >        | echo hi > file.txt  | 把输出写入文件（覆盖） |
| 标准输出追加         | >>       | echo hi >> file.txt | 把输出追加到文件       |
| 错误输出重定向       | 2>       | ls xx 2> err.log    | 把错误写入文件         |
| 同时重定向输出和错误 | &>       | cmd &> all.log      | 两者都写入同一文件     |
| 输入重定向           | <        | wc -l < file.txt    | 从文件读输入           |



------





# ** 一个有趣的组合例子**



```
grep "root" /etc/passwd /not_exist.txt > found.txt 2> error.log
```

执行逻辑：



1. 去 /etc/passwd 里找 root，把找到的写进 found.txt；
2. 遇到 /not_exist.txt 报错，把错误写进 error.log。





程序的正常输出和错误信息，就这样被分流开了，互不打扰。

这其实就像在厨房里：主厨一边做菜（stdout），一边在抱怨（stderr）——

我们把他俩的声音录进不同的麦克风就行 😄



------





# **更底层一点的小秘密**





其实每个 Linux 进程启动时，内核都会自动帮它打开这三个文件描述符：



- 0 → /dev/stdin
- 1 → /dev/stdout
- 2 → /dev/stderr





它们本质上都指向系统设备（比如终端）。

所以当你执行重定向命令时，其实就是在让进程的“文件指针”指向别的地方。



------





# **✨ 最后说点哲学**





Linux 的设计哲学是“**一切皆流（stream）**”。



命令之间通过“管道（|）”传递数据，

输入输出都只是流的方向问题。



这也解释了为什么：



- ls | grep "txt" 可以自然地工作；
- 以及为什么 >、2>、< 这么灵活。





因为在 Linux 世界里，

**命令不是孤岛，它们都在流动。**



------





# **总结**



| **名称** | **代号** | **默认设备** | **功能**       |
| -------- | -------- | ------------ | -------------- |
| stdin    | 0        | 键盘         | 程序的输入     |
| stdout   | 1        | 屏幕         | 程序的正常输出 |
| stderr   | 2        | 屏幕         | 程序的错误输出 |

再一句话总结：



> 🧩 **stdin 是耳朵，stdout 是嘴巴，stderr 是抱怨的嘴巴。**
