# Linux 文件权限与所有权详解

Linux 的权限系统是多用户协作与系统安全的核心。  
通过用户（User）、组（Group）、其他人（Others）的权限控制，实现灵活的访问管理。

---

## 一、文件权限的基本组成

每个文件或目录都包含三种主体的访问权限：

| 主体            | 含义         | 权限标识 |
| --------------- | ------------ | -------- |
| **u（user）**   | 文件的所有者 | rwx      |
| **g（group）**  | 文件所属组   | rwx      |
| **o（others）** | 其他所有用户 | rwx      |

使用 `ls -l` 可以查看权限：
```bash
ls -l
```

一般可以用简写 `ll`代替

输出示例：

```text
-rw-rw-r-- 1 william devteam 1234 Oct  9 project.txt
```

解释如下：

最前面的一个符号（比如`-` , `d`）表示文件的类型，后面的三个三个为一组

| **部分** | **含义**                               |
| -------- | -------------------------------------- |
| -        | 文件类型（- 表示普通文件，d 表示目录） |
| rw-      | 所有者的权限：读、写                   |
| rw-      | 所属组的权限：读、写                   |
| r--      | 其他用户的权限：只读                   |
| william  | 文件所有者                             |
| devteam  | 文件所属组                             |



## **二、修改文件权限**

### **1. 使用** **chmod****修改权限**

格式：

```
chmod [选项] 权限 文件名
```

示例：

```
chmod u+x script.sh     # 给文件所有者添加执行权限
chmod g+rw project.txt  # 给组添加读写权限
chmod o-rw secret.txt   # 移除其他人的读写权限
chmod 755 run.sh        # 数字形式设置权限
```

数字形式说明：

| **数值** | **权限** | **含义** |
| -------- | -------- | -------- |
| 7        | rwx      | 读写执行 |
| 6        | rw-      | 读写     |
| 5        | r-x      | 读执行   |
| 4        | r–       | 只读     |
| 0        | —        | 无权限   |

## **三、用户与组所有权**

每个文件有一个所有者（user）和一个组（group）。

### **1. 查看文件所有权**



```
ls -l
```



### **2. 修改文件所有者**



```
sudo chown 新用户 文件
```

示例：

```
sudo chown william demo.txt
```



### **3. 修改文件所属组**



```
sudo chgrp 新组 文件
```

或一次性修改两者：

```
sudo chown 用户:组 文件
```

示例：

```
sudo chown william:devteam project.txt
```



## **四、组权限的意义**



在多人协作的环境中，**组权限非常重要**。



> 同一个组内的成员，只要文件组权限允许（如 g+rw），即使不是文件所有者，也能修改文件！

示例：

```
sudo chgrp devteam project.txt
chmod g+rw project.txt
```

当用户 alex 和 william 都属于 devteam 时，

他们都能编辑该文件。



如果文件组是 root，则 alex 将无权修改。



## **五、用户与组管理命令**



| **操作**   | **命令**                         | **说明**                |
| ---------- | -------------------------------- | ----------------------- |
| 创建新组   | sudo groupadd devteam            | 新建组                  |
| 更换主组   | sudo usermod -g devteam william  | 修改默认组              |
| 添加附属组 | sudo usermod -aG devteam william | 加入协作组              |
| 查看组     | groups william                   | 查看所属组              |
| 临时切换组 | newgrp devteam                   | 切换当前 shell 的组身份 |



## **六、权限优先级与访问逻辑**



当用户访问文件时，Linux 按以下顺序判断权限：



1. 是否是 **文件所有者**？ → 使用 user 权限
2. 否则是否属于 **文件所属组**？ → 使用 group 权限
3. 否则使用 **others（其他人）** 权限



> 只会匹配其中一种，不会叠加判断。



## **七、重定向与权限的关系**



命令重定向时，也受文件权限限制：

```
ls /fake/directory > output.txt 2>&1
```



### **解释：**

- \>：将标准输出（stdout）写入 output.txt
- 2>&1：将标准错误（stderr）也重定向到相同位置

简写形式：

```
ls /fake/directory &> output.txt
```



## **八、管道与** 

## **tee** **命令**



管道符 | 将一个命令的输出（stdout）作为另一个命令的输入（stdin）：

```
ls -la /etc | less
```

同时输出到文件与屏幕：

```
ls | tee peanuts.txt
```

> tee 相当于一个分流器，一份写到文件，一份继续传递到标准输出。



## **九、示例总结**



| **命令**                 | **作用**                |
| ------------------------ | ----------------------- |
| chmod g+rw file          | 给组添加读写权限        |
| chown william file       | 改文件所有者            |
| chgrp devteam file       | 改文件组                |
| usermod -aG devteam alex | 让 alex 加入 devteam 组 |

|                          |                         |



## **十、权限设计原则**



- **最小权限原则**：只给需要的用户必要权限
- **使用组共享**：通过组权限共享资源，而非 777
- **避免使用 root**：仅在必要时使用管理员权限
- **保持权限一致性**：团队共享目录应统一组与权限设定



**结语：**

> 理解文件权限不仅是学 Linux 的基础，更是系统安全与协作管理的核心。

> 合理地使用 chmod、chown、chgrp、usermod 能让你安全又高效地管理服务器和项目环境。
