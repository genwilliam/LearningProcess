> 视图可以理解为 **一个“虚拟表”**，它本质上是 **一个存储起来的 SQL 查询**，但看起来像一个普通的表。其实它背后只是一个 SQL 查询

假设你有一个 `Homework` 表：
|SNo|T1|T2|T3|
|---|---|---|---|
|1001|80|85|90|
|1002|70|75|80|

你经常需要查看学生的平均成绩，那你可以创建一个 **视图**：
```mysql
CREATE VIEW v_avg_homework AS
SELECT SNo, (T1 + T2 + T3)/3 AS AvgScore
FROM Homework;

```
然后你以后只需要：
```mysql
SELECT * FROM v_avg_homework;
```
就相当于执行了上面的查询，结果直接返回你需要的格式，不需要每次都写 AVG 的逻辑

## 视图的注意事项：

- 视图本身**不存数据**，查询视图时它会重新执行 SQL；
    
- 不能在某些视图上执行 `INSERT` 或 `UPDATE`（尤其是包含聚合函数、JOIN、DISTINCT 等）；
    
- 性能上视图不一定比直接写 SQL 快，因为本质还是执行原查询；
    
- **视图可以嵌套视图**，但要注意维护和性能。
